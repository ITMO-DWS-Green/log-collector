# log-collector

## Процесс разработки

Мы используем **trunk-based development** с `main` в качестве единственной долгоживущей ветки.

- **Короткоживущие ветки:** Для каждой задачи создавайте отдельную ветку от актуальной `main`. Используйте понятные названия, например `feature/user-auth` или `fix/login-error`.
- **Pull Request:** Все изменения должны попадать в `main` через Pull Request. Прямые изменения в `main` запрещены.
- **Code Review:** Для слияния необходим как минимум один аппрув от другого участника команды.
- **CI:** Все обязательные проверки CI должны успешно завершиться до слияния.
- **Небольшие изменения:** Старайтесь делать небольшие Pull Request и чаще сливать готовые изменения.
- **Удаление веток:** После слияния удаляйте использованные ветки.

Ветка `main` всегда должна оставаться стабильной и готовой к дальнейшей разработке.
