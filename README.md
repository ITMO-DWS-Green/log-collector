# log-collector

## Процесс разработки

Мы используем **trunk-based development** с `main` в качестве единственной долгоживущей ветки.

- **Короткоживущие ветки:** Для каждой задачи создавайте отдельную ветку от актуальной `main`. Используйте понятные названия, например `feature/user-auth` или `fix/login-error`.
- **Pull Request:** Все изменения должны попадать в `main` через Pull Request. Прямые изменения в `main` запрещены.
- **Code Review:** Для слияния необходим как минимум один аппрув от другого участника команды.
- **CI:** Все обязательные проверки CI должны успешно завершиться до слияния.
- **Небольшие изменения:** Старайтесь делать небольшие Pull Request и чаще сливать готовые изменения.
- **Удаление веток:** После слияния удаляйте использованные ветки.

Ветка `main` всегда должна оставаться стабильной и готовой к дальнейшей разработке.

## Структура проекта

Модульный монолит на Java 21 и Spring Boot плюс отдельное приложение-генератор. Модули общаются через интерфейсы в `core`, поэтому их можно разрабатывать параллельно. Подробно — [docs/architecture/modules.md](docs/architecture/modules.md).

| Модуль | Назначение |
|---|---|
| `core` | Единый формат данных и интерфейсы между модулями |
| `generator` | Имитация сервисов, сбои и разметка |
| `ingestion` | Приём потока и файлов |
| `storage` | Хранилища |
| `detection-rules` / `detection-ml` | Два подхода к обнаружению |
| `incidents` | Объединение, ранжирование, объяснение |
| `evaluation` | Сравнение подходов |
| `response` | Ответственная команда и чат инцидента |
| `app` | Конвейер и REST API |

## Запуск

```bash
./gradlew build                 # сборка и тесты
./gradlew :app:bootRun          # log-collector на http://localhost:8080
./gradlew :generator:bootRun    # генератор данных
docker compose up --build       # всё сразу в контейнерах
```
