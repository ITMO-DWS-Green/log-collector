# Интеграция с Zabbix 7.0

Справка по механизмам, на которых стоит расширение. Источник — документ Евгения Матеюка «Расширение Zabbix на Java и JS» и исходники Zabbix 7.0 (`github.com/zabbix/zabbix`, ветка `release/7.0`). Песочница для экспериментов — [zabbix-sandbox](https://github.com/ITMO-DWS-Green/zabbix-sandbox).

## Что можно и что нельзя

| Можно | Нельзя (только на C внутри сервера) |
|---|---|
| Получать значения и события в реальном времени (коннектор) | Добавить свою функцию в выражения триггеров |
| Читать историю, тренды, всю конфигурацию (API) | Менять логику сервера |
| Комментировать проблемы, менять важность, отмечать симптомы | Перехватывать данные до записи в историю |
| Писать свои значения в элементы (`history.push`) | |
| Добавлять страницы и виджеты в интерфейс (модули) | |

## Коннектор → наш сервис
- Включить на сервере: `StartConnectors=1` (по умолчанию 0).
- Создать: Administration → General → Connectors или `connector.create`.
- Тип данных: события (`data_type: 1`) — нужно для MVP; значения метрик (`data_type: 0`) — для ML позже.
- Фильтр по тегам: отправляем только события хостов стенда.
- Формат — построчный JSON (NDJSON). Ответ сервиса 200–204, иначе Zabbix повторяет отправку (до 5 попыток), потом данные теряются — догоняем через API.

Событие о проблеме:
```json
{"clock":1761382800,"ns":0,"value":1,"eventid":42,"name":"gateway: доля 5xx выше 10%",
 "severity":3,"hosts":[{"host":"gateway","name":"gateway"}],"groups":["test-server"],
 "tags":[{"tag":"service","value":"gateway"}]}
```
Закрытие проблемы: `{"clock":…,"ns":…,"value":0,"eventid":43,"p_eventid":42}`.

## Наш сервис → API
JSON-RPC 2.0, `POST /api_jsonrpc.php`, заголовок `Authorization: Bearer <токен>`. Токен — постоянный API-токен сервисного пользователя (Users → API tokens).

| Задача | Методы |
|---|---|
| Хосты, теги, элементы | `host.get`, `item.get` |
| История метрик и логов за окно | `history.get` (лог — `history: 2`) |
| Проблемы и события, догон пропусков | `problem.get`, `event.get` |
| Комментарий с разбором | `event.acknowledge` с сообщением |
| Отметка симптома (если успеем) | `event.acknowledge`, есть с 6.4 |
| Свои значения, например оценка ML (если успеем) | `history.push` |
| Настройка коннектора | `connector.create`, `connector.get` |

## Оповещение в Telegram
Через штатные средства Zabbix ([D-006](decisions.md)):
1. Тип оповещения Telegram (встроенный вебхук) с токеном бота.
2. Пользователь Zabbix на каждую команду, в медиа — ID группового чата команды.
3. Действие по тегу `team`: при обновлении проблемы (наш комментарий) отправить сообщение с текстом комментария.

## Модуль интерфейса
Лежит в `/usr/share/zabbix/modules/<имя>/`, включается в Administration → General → Modules.
```
zabbix-module/
  manifest.json     id, namespace, действия, подключение JS
  Module.php        пункт меню
  actions/          контроллеры: страница и прокси в наш сервис
  views/            PHP-шаблон, внутри только контейнер для JS
  assets/js/app.js  весь интерфейс
```
JS ходит в наш сервис через PHP-действие модуля: работают сессия и права пользователя Zabbix, не нужен CORS. Контроллер наследует `CController` и реализует `checkInput`, `checkPermissions`, `doAction`.

## Тонкие места
- Изменения конфигурации через API (теги, триггеры) начинают работать после перечитывания кэша сервером — до минуты (`CacheUpdateFrequency`).
- Токен сервиса: чтение групп хостов стенда и право комментировать проблемы.
- В песочнице есть элементы `testserver.scenario` и `testserver.status` — по ним видно включённый сбой. Разбор их не читает (NFR-10).
