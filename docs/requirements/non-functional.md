# Нефункциональные требования

Статус: **черновик** ([задача #3](https://github.com/ITMO-DWS-Green/log-collector/issues/3)). Значения — предложение команды, утверждаем с заказчиком.

| ID | Тема | Требование | Значение | Источник |
|---|---|---|---|---|
| NFR-01 | Совместимость | Работает с Zabbix 7.0 LTS без изменения его ядра: только коннектор, API, модуль интерфейса, действия | Zabbix 7.0 | |
| NFR-02 | Развёртывание | Стенд (Zabbix, test-server, наш сервис, модуль) поднимается одной командой на чистой машине по README | `docker compose up` | |
| NFR-03 | Скорость разбора | Время от события о проблеме до комментария в Zabbix | ≤ 60 с | предложено |
| NFR-04 | Окно анализа | Сколько истории перед проблемой смотрим при разборе | 15 мин, настраивается | предложено |
| NFR-05 | Нагрузка | Стенд: 4 сервиса × ~10 метрик раз в 30–60 с + логи до 50 строк/с на сервис; сервис справляется без отставания | замер в спринте 3 | |
| NFR-06 | Надёжность приёма | Отвечаем коннектору 200–204; если сервис был недоступен, пропуски дозапрашиваем через `history.get` | — | |
| NFR-07 | Хранение | Своя БД хранит только инциденты, разборы, разметку и оценки; метрики и логи остаются в Zabbix | инциденты — 90 дней | предложено |
| NFR-08 | Права | Токен API сервиса: чтение нужных групп хостов, запись комментариев к проблемам; без прав администратора | — | |
| NFR-09 | Данные наружу | Логи и метрики не уходят во внешние сервисы. LLM — только с маскированием и с разрешения заказчика | — | вопрос заказчику |
| NFR-10 | Честная оценка | Разбор не видит разметку и элементы, по которым видно включённый сценарий (`testserver.scenario`, `testserver.status`) | — | |
| NFR-11 | Качество кода | Сборка и тесты в CI на каждый PR, тесты на логику разбора | — | |

Когда значение утверждено — пишем в «Источник», кто и когда.
