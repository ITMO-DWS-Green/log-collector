# Единый язык

Эти слова одинаково используют заказчик, аналитики и разработчики — в разговорах, задачах, интерфейсе и коде. Нет термина или его понимают по-разному — сначала дополняем этот файл.

**Главная цепочка:** сбой на сервисе → в Zabbix срабатывает триггер и открывается проблема → коннектор присылает событие → связанные проблемы объединяются в инцидент → разбор называет подозреваемых и приводит доказательства → разбор уходит комментарием в Zabbix и оповещением ответственной команде.

Три правила, которые чаще всего нарушают:
- «Алерт» не говорим. Это либо **проблема** (в Zabbix сработал триггер), либо **оповещение** (сообщение человеку).
- «Ошибка» — это уровень записи лога или ответ 5xx, а не сбой. Что случилось с сервисом — **сбой**, что увидели мы — **инцидент**.
- **Разметка** — это правда о сбое со стенда. Разбор её никогда не видит.

## Zabbix

| Термин | Что значит | У нас |
|---|---|---|
| Хост | Наблюдаемый объект в Zabbix | Один сервис: gateway, orders, payments, database |
| Элемент (item) | Что собирается: одна метрика или один лог | Метрика или лог сервиса |
| Лог-элемент | Элемент, значения которого — строки лога | Источник доказательств из логов |
| Тег | Пара «имя — значение» у хоста, элемента или триггера | `service`, `calls`, `team` — для карты связей и справочника |
| Триггер | Условие над значениями элемента с ручным порогом | Базовый сигнал о сбое |
| Проблема | Открытое срабатывание триггера; закрывается, когда условие перестало выполняться | Входной сигнал для разбора |
| Событие | Запись о возникновении или закрытии проблемы | Приходит к нам через коннектор |
| Коннектор | Механизм Zabbix 7.0, который отправляет события или значения во внешний сервис потоком | Наш вход в реальном времени |
| API | JSON-RPC интерфейс Zabbix | История, хосты, комментарии к проблемам |
| Подтверждение (acknowledge) | Действие над проблемой: комментарий, смена важности, отметка симптома | Так мы пишем разбор в Zabbix |
| Действие (action) | Правило Zabbix «при таком событии — оповестить таких-то» | Отправка разбора в Telegram |
| Модуль | Расширение веб-интерфейса Zabbix: своя страница или виджет | Карточка инцидента, страница точности |

## Стенд и разметка

| Термин | Что значит | Не путать |
|---|---|---|
| Стенд, test-server | Четыре сервиса, вызывающих друг друга, со сбоями по кнопке | Не прод |
| Сценарий | Один вид сбоя на одном сервисе: 5xx, задержка, падение, утечка памяти и т. д. | — |
| Плейбук | Последовательность сценариев по времени, общий `scenarioId` на прогон | — |
| Сбой | Нарушение работы сервиса, включённое сценарием | Не «инцидент» |
| Разметка | Правда о сбое: сценарий, тип, сервис-источник, начало, конец | Не результат разбора |
| Сервис-источник | Сервис, где сбой начался. В разметке известен точно | Подозреваемый — это наша гипотеза |
| Каскад | Сбой в одном сервисе вызывает ошибки у тех, кто его вызывает | — |

## Разбор

| Термин | Что значит | Не путать |
|---|---|---|
| Инцидент | Группа связанных проблем с одной причиной | Одна проблема — ещё не обязательно инцидент |
| Карта связей | Кто кого вызывает, по тегам хостов | — |
| Норма | Обычное поведение метрики сервиса, вычисленное из её истории | Не ручной порог триггера |
| Отклонение | Метрика заметно ушла от нормы; у отклонения есть момент начала | — |
| Подозреваемый | Сервис, который может быть источником; список ранжирован | Не «виновник» — это гипотеза |
| Доказательства | Отклонившиеся метрики и характерные строки логов вокруг начала инцидента | — |
| Разбор | Подозреваемые + доказательства + короткий текст | Гипотеза, а не диагноз |
| Базовый подход | Источник — сервис, чей триггер сработал первым | То, с чем сравниваем наш разбор |
| Команда | Люди, отвечающие за сервис | Не наша команда разработки |
| Справочник «сервис — команда» | Кто отвечает за какой сервис; тег `team` у хоста | — |
| Оповещение | Сообщение человеку о разборе | Не «проблема» |

## Оценка качества

Считается по разметке на одних и тех же прогонах для нашего разбора и базового подхода.

| Термин | Что значит |
|---|---|
| Точность top-1 | Доля инцидентов, где сервис-источник назван первым |
| Точность top-3 | Доля инцидентов, где сервис-источник в первых трёх |
| Пропуск | Сбой из разметки, по которому не появился инцидент |
| Ложный инцидент | Инцидент, которому не соответствует ни один сбой |
| Время до разбора | От начала сбоя по разметке до комментария в Zabbix |
