# Как работаем

## Код
Trunk-based development: ветка от свежего `main` под задачу (`feature/…`, `fix/…`), слияние через Pull Request с одним аппрувом и зелёным CI, ветку после слияния удаляем. Подробно — в [README](../../README.md).

В названии PR или ветки указываем номер задачи, в описании PR — `Closes #N`, чтобы задача закрылась сама.

## Задачи
- Любая работа — задача в [Issues](https://github.com/ITMO-DWS-Green/log-collector/issues).
- У задачи есть метка области и спринт (milestone).
- Описание отвечает на «что сделать» и содержит чек-лист «Готово, когда».

| Метка | Область |
|---|---|
| `генератор` | Синтетические логи, метрики и сбои |
| `приём данных` | Приём, единый формат, хранение |
| `обнаружение` | Правила и статистические пороги |
| `ml` | Модель машинного обучения |
| `инциденты` | Объединение, ранжирование, объяснение |
| `реакция` | Ответственная команда и чат инцидента |
| `веб-интерфейс` | Веб-интерфейс |
| `инфраструктура` | Репозиторий, CI, стенд |
| `аналитика` | Требования, документация, согласование |
| `исследование` | Нужно разобраться перед реализацией |

## Доска
Backlog → Ready → In progress → In review → Done. Берём задачи из Ready; в работе у одного человека — не больше одной-двух задач.

## Спринты
| Спринт | Фокус |
|---|---|
| 1 | Команда, требования, анализ аналогов, инфраструктура |
| 2 | Данные: генератор, сбои с разметкой, приём, единый формат |
| 3 | Обнаружение: правила, пороги, ML, объединение в инциденты |
| 4 | Сравнение подходов, ранжирование сервисов |
| 5 | Объяснение, реакция, веб-интерфейс, демо |

## Definition of Done
- [ ] выполнены все пункты «Готово, когда» в задаче;
- [ ] код в `main` через PR с аппрувом;
- [ ] CI зелёный, есть тесты на новую логику;
- [ ] если изменились термины, требования или решения — обновлена база знаний.
